# Дизайн-система therapy-scheduling

Погоджений варіант: **«Airy glass»** (варіант 6). Натхнення — концепт MindBridge (Dribbble): повітряний
блакитно-лавандовий фон, «скляні» панелі з великим радіусом, вузька смуга круглих іконок зліва, темно-синя пігулка для
основної дії. Логотип, назву, фото й тексти концепту **не копіюємо**.

Візуальний еталон — `docs/design/design-preview.html` (статичний макет). Цей файл нормативний: якщо макет і текст розходяться,
правий текст.

## 1. Принципи

- Світло, повітряно, спокійно — але читабельно: текст завжди на достатньо щільному склі, контраст рахується з запасом.
- Одна основна дія на картку — темно-синя пігулка. Решта — біла пігулка з синьою межею або скляна.
- Статус ніколи не передається лише кольором: **текст бейджа + його іконка + фактура картки** (див. 2.3).
- Градієнтні плями фону й штриховка — декор, не несуть змісту самі по собі. Декоративних «куль» на картках немає.
- Тексти PM, імена полів форм, `data-testid`, ролі `alert` / `status` і структура server actions **не змінюються**.

## 2. Токени

Усі значення — CSS-змінні в `src/app/globals.css`, Tailwind бачить їх через `@theme inline`. Сирі класи палітри
Tailwind (`zinc-*`, `red-*`, `green-*`, `amber-*`, `bg-foreground` тощо) у `src/` після впровадження не лишаються.
Темна тема — `@media (prefers-color-scheme: dark)`.

### 2.4 Типографіка

- Шрифт — **Manrope** через `next/font/google` у `layout.tsx` (це не нова npm-залежність; Geist і Geist Mono прибрати).
  Прибрати `font-family: Arial` з `body`. Глобально `font-variant-numeric: tabular-nums` — час вирівнюється без моноширинного шрифту.
- Ваги 400, 500, 600, 700.
- Заголовок сторінки: 44/52, **400**, `letter-spacing: -0.025em` (34/40 на телефоні). Заголовок панелі: 22/28, 500.
  Імʼя в картці слота: 15/20, 600. Текст: 14/20. Підпис поля: 13/18, 600. Бейдж: 12, 700. Дрібний текст: 12/16.

### 2.5 Радіуси, відступи, тіні

- Радіуси: `r-sm` 10px, `r-md` 14px (рядки списків, варіанти), `r-lg` 24px (картки слотів, порожній стан),
  `r-xl` 28px (панелі), `pill` 999px (кнопки, поля, бейджі, повідомлення, плашка акаунта).
- Відступи: padding панелі 26px (20px на телефоні); між панелями 24px; висота години в сітці ≥ 104px.
- Тіні: `shadow` — `0 1px 1px rgba(27,38,88,.03), 0 18px 48px rgba(44,62,140,.08)`;
  `shadow-pop` — `0 2px 4px rgba(27,38,88,.06), 0 24px 56px rgba(44,62,140,.18)`; основна кнопка — `0 8px 20px rgba(27,38,88,.22)`.

## 3. Каркас

- **AppShell** для всіх сторінок, крім `/login`: сітка `96px | 1fr` на тлі градієнта з плямами.
- **Бічна смуга** (`aside`) без фону: знак угорі (два перекриті кола блакитного й лавандового градієнтів, 48px —
  свій, не серце MindBridge), нижче `nav aria-label="Main"` з круглими скляними кнопками 56px, активна — 64px,
  фон `navy`, іконка `on-navy`, `aria-current="page"`. Унизу — кнопка «Sign out» (наявна форма `signOut`).
- **Назва пункту обовʼязкова:** `aria-label` на кожній кнопці + видима підказка (пігулка `navy`) праворуч на hover і focus.
- **Пункти за роллю:** staff — Home, Clients, Slots; `therapist` — Home, My schedule. Іконки: будинок, люди, календар, годинник.
- **Шапка контенту:** зліва заголовок сторінки й опис `muted`; справа скляна пігулка акаунта (email 600, роль `muted`,
  коло з першою літерою).
- Посилання «Home» / «Back» у шапках сторінок прибрати: їх замінює смуга.
- AppShell — у спільному `src/app/(app)/layout.tsx` для `/`, `/clients`, `/slots`, `/my-schedule`, а не на сторінках:
  між розділами смуга не перемальовується, а `loading.tsx` розділу замінює лише контент (PR #15).
- Якщо перехід на пункт смуги чекає сервера (скелетон розділу ще не завантажено наперед, `useLinkStatus`), іконка
  кнопки стає спінером того ж розміру; для вже завантаженого розділу одразу видно скелетон, і спінера немає.
- **До 760px** смуга стає плаваючою скляною панеллю-пігулкою внизу екрана (52px кнопки в ряд, знак ховається);
  контенту додається нижній відступ 96px. Email і роль у плашці ховаються. Горизонтальної прокрутки бути не повинно.

### 4.1 Select

- Тригер — пігулка 48px: коло з ініціалами вибраного (якщо є), текст 600, шеврон у колі праворуч; плейсхолдер `muted`.
- Спливаюча панель `glass-hi` + blur, `shadow-pop`, радіус 24px; варіанти 48px з ініціалами; вибраний — фон `glass`, 700 і галочка `navy`.
- Патерн WAI-ARIA «select-only combobox» (`role="combobox"`, `aria-expanded`, `aria-controls`, `aria-activedescendant`,
  `role="option"` + `aria-selected`). Клавіатура: Enter / Space / ↓ відкривають; ↑ ↓ Home End; Enter вибирає; Esc
  закриває й повертає фокус; набір літер.
- Значення — `<input type="hidden" name="client_id">` у формі `HoldSlotForm`.

### 4.2 Вибір терапевта й дня на `/slots`

Нативні `<select>` і `<input type="date">` зникають. Ліва колонка — та сама **GET-форма**:

- **ChoiceList «Therapist»**: кожен терапевт — кнопка `type="submit" name="therapist" value=<id>` з `aria-pressed`
  (вибраний — `true`). Рядок 60px: коло з ініціалами, імʼя 600, праворуч кільце-радіо; вибраний — фон `glass-hi`,
  межа `glass-edge`, тінь, заповнене коло `navy` з галочкою. Поточна дата йде прихованим `<input name="date">`.
- **Calendar «Day»**: місяць із кнопками попереднього / наступного (44×44, перемикають лише вигляд, без відправки),
  тиждень з понеділка (Mo … Su). Сітка `repeat(7, minmax(0, 1fr))` без проміжків між колонками; день — коло `width: 100%; max-width: 44px; aspect-ratio: 1`, тож календар ніколи не виходить за межі панелі. Кожен день — `type="submit" name="date" value="YYYY-MM-DD"`, `aria-pressed` для
  вибраного, `aria-label="YYYY-MM-DD"` (для сьогодні — «, today»). Вибраний — коло `navy`; сьогодні (America/Los_Angeles) —
  крапка `blue` під числом; дні інших місяців — `muted` 50%. Поточний терапевт — прихований `<input name="therapist">`.
  Клавіатура: Tab до сітки, стрілки по днях (roving tabindex), PageUp / PageDown — місяць.
- Кнопка «Show» більше не потрібна: вибір одразу відправляє форму. Без JavaScript усе працює, бо це звичайні submit-кнопки.
- З JavaScript обидві форми (позначені `data-navigate`) перехоплює клієнтський `SlotsNavigation`: збирає URL з
  `new FormData(form, submitter)` і робить `router.push` у `startTransition`, тож перехід клієнтський, а поки він
  чекає сервера, права колонка тьмяніє (`data-pending`, `aria-busy`) і live-область AppShell оголошує «Loading…».
  `next/form` не підходить: він не передає `name`/`value` натиснутої кнопки.
- `Calendar` не перемонтовуємо (`key`) на зміну дня: кнопка дня, яку натиснули, зберігає фокус після переходу.

## 5. Сторінки

- **`/slots`**: дві колонки `360px | 1fr` (одна колонка до 1000px).
  - Ліва: панелі «Therapist» і «Day» (4.2).
  - Права, панель «<Терапевт> — <дата>»: заголовок зліва; справа поле «Client to hold a slot for» (Select);
    під ними `ActionMessage`.
  - **DayGrid** — рядок на кожну годину, зліва година `muted` 500 (колонка 64px), роздільник `line`; у рядку `SlotCard`:
    - **Free:** бейдж Free + кнопка «Hold HH:MM» (primary) праворуч;
    - **Held:** імʼя 600, «Held until …» `muted`, бейдж Held, кнопка «Confirm HH:MM» (secondary);
    - **Confirmed:** імʼя, бейдж Confirmed, без дії.

    Кнопки й далі надсилають форми через атрибут `form` з `name="slot_start"` / `name="hold_id"`. `data-testid="slot-list"` —
    на контейнері сітки. На телефоні кнопка переходить під текст на всю ширину картки.
  - **Лінія «зараз»** (опційно, лише коли вибрано сьогоднішній день): 2px `blue` з точкою 10px і пігулкою «Now HH:MM»
    біля колонки годин; проходить під картками (`z-index`), `aria-hidden`.
  - Панель «Expired holds»: опис `muted`, список карток Expired (час 600, імʼя, бейдж), `data-testid="expired-holds"`.
- **`/my-schedule`**: панель на кожен із 7 днів (заголовок — дата, для сьогодні «, today»), всередині `DayGrid` без дій;
  лінія «зараз» — лише в панелі сьогоднішнього дня.
- **`/clients`**: панель «New client» (Field + Input для Name і Email, кнопка Create client — primary, `ActionMessage`);
  панель «All clients» — список рядків 56px: коло з ініціалами, імʼя 600, email `muted`, `data-testid="client-list"`.
- **`/`**: заголовок «Home», панель «Account» з парами «підпис / значення» (Email, Role) у 2 колонки; `data-testid` як зараз.
- **`/login`**: без смуги; на тлі градієнта по центру одна скляна панель 400px (знак, «Practice scheduling», `h1`
  «Sign in»), ті самі Field / Input / SubmitButton.

## 6. Що не можна змінювати

- Тексти PM (статуси, повідомлення, «No free slots on this day.» тощо) і наявні тексти UI.
- **Інтерфейс лише англійською:** заголовки, підписи, кнопки, помилки, `aria-label`, `<title>` і `lang="en"`.
  Українською лишаються коментарі в коді, документація й назви тестів; дані (імена людей) показуємо як є.
- Імена полів: `full_name`, `email`, `client_id`, `therapist_id`, `slot_start`, `hold_id`; GET-параметри `therapist`, `date`.
- `data-testid`: `user-email`, `user-role`, `client-list`, `slot-list`, `no-free-slots`, `expired-holds`.
- `useActionState`, server actions у `actions.ts`, `requirements/`, `openspec/specs/`, міграції.
- Нові npm-залежності — лише з окремого погодження.

## 7. Доступність (WCAG 2.1 AA)

- Контраст тексту ≥ 4.5:1, меж контролів, кілець радіо й focus ≥ 3:1 — значення в таблицях розділу 2, в обох темах.
- Focus ring: `outline: 2px solid var(--blue); outline-offset: 2–3px` на всіх інтерактивних елементах.
- Цілі натискання ≥ 44×44 px (кнопки смуги 56px, дні календаря — кола 44×44 у колонці 360px; на екранах вужчих за ~375px дні стискаються до ~41px, щоб календар не вилазив).
- Кнопки смуги без видимого тексту мають `aria-label` і видиму підказку на focus.
- Анімація спінера й пульс скелетона вимикаються при `prefers-reduced-motion: reduce`.

## 8. Перевірка після впровадження

`npm run lint` (0 warnings), `npm run typecheck`, `npm test`, `npm run build`, `npm run ac:coverage`.
Плюс ручна перевірка: світла й темна теми, ширина 390px без горизонтальної прокрутки, повний прохід клавіатурою
(смуга, вибір терапевта, календар, Select, кнопки Hold / Confirm).
